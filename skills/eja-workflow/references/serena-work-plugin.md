# Serena: проверенный плагин Kimi Work

Пользователь указал этот плагин как рабочий образец. Устройство проверено по исходникам, установленной копии, задаче Windows и слушающему процессу 2026-11-03. Это конфигурация **Kimi Work**, не инструкция для Kimi Code.

## Из чего состоит существующая установка Eja

1. Serena1.7.0 установлена как `serena-agent` через uv. Доступна команда `serena.exe`.
2. Сервер работает отдельно от Kimi с `streamable-http` на `127.0.0.1:9121`.
3. Плагин `serena` версии `0.1.0+local.20261102-122152` — MCP-коннектор: `kimi.plugin.json` и перевод `locales/zh-CN.json`. В нём нет скиллов, hooks, sessionStart, systemPrompt и кода запуска сервера.
4. Ключевой **фрагмент** его манифеста:

```json
{
  "mcpServers": {
    "serena": {
      "url": "http://127.0.0.1:9121/mcp"
    }
  }
}
```

Это не полный устанавливаемый манифест: остальные метаданные и локализации создаёт штатный plugin-builder.

Исходник на этой машине: `C:/Users/Eja/AppData/Roaming/kimi-desktop/daimon-share/plugin-sources/personal/serena`. Личная регистрация хранится под `daimon/plugin-market/personal/serena.json`, поле `sourcePath` указывает исходник. Work копирует его в `daimon/runtime/kimi-code/home/plugins/managed/serena`. Правь только исходник, не managed-копию. На другой машине найди действующий share-dir и регистрацию вместо копирования путей Eja.

## Как сервер запускается на Windows

Задача `SerenaMcpServer` с триггером входа пользователя запускает `wscript.exe` с `%USERPROFILE%/.serena/serena-mcp-hidden.vbs`. Этот небольшой VBS запускает `serena-mcp.cmd` скрыто. CMD добавляет установленный .NET в `DOTNET_ROOT`/`PATH` для C# и вызывает:

```text
serena start-mcp-server --transport streamable-http --host 127.0.0.1 --port 9121 --context agent --open-web-dashboard false
```

В фактическом CMD используется абсолютный путь к `serena.exe`. Задача работает с обычными правами пользователя, `IgnoreNew`, без настроенного restart. Это автозапуск при входе, а не доказательство непрерывной работы или восстановления после сбоя. Не создавай второй сервер на том же порту. Проверь доступность .NET для C# по фактической установке, не копируй чужой PATH.

## Как подключить или создать такой плагин

1. **Проверь существующее.** Если Kimi уже видит инструменты Serena, проверь связь и используй подключение. Если коннектор есть, а сервер недоступен, исправь причину запуска/связи; не переустанавливай весь плагин автоматически.
2. **Если сервера нет**, установи его по [официальному Quick Start](https://github.com/oraios/serena#quick-start), затем запусти поддерживаемым способом. Для HTTP подтверди настоящий локальный host/port/path; `9121/mcp` — проверенный адрес Eja, не обязательный адрес для всех машин. Конфигурирование постоянного автозапуска — отдельная часть разрешённой настройки. Фоновый запуск должен быть скрытым.
3. **Если коннектора нет**, прочитай установленный Work `plugin-builder/SKILL.md` и `create_plugin.py --help`. Поддерживаемая форма создания нового коннектора:

```text
python <plugin-builder>/scripts/create_plugin.py serena --type mcp --mcp-url <проверенный-URL> --path <новый-каталог-исходников> --display-name Serena --description "Semantic code tools through the local Serena MCP server" --locale en-US
```

Это шаблон команды: подставь обнаруженные пути и проверенный URL. Если имя `serena` уже установлено/зарегистрировано, используй его исходник, не создавай конфликтующее имя и не передавай `--force`. Генератор создаёт полный нативный манифест и локализацию; ключ `mcpServers.serena.url` должен совпасть с работающим сервером. Серверный пакет не копируется внутрь плагина.
4. Выполни штатные `validate_plugin.py <source-dir>` и `register_personal.py <source-dir>` с фактическими параметрами среды Work. Затем установи через **Work → Плагины → Личные**; при изменении существующего исходника повысь версию и используй **Обновить**. Регистрация сама по себе ничего не устанавливает. Не заявляй, что нажал кнопку, если интерфейс недоступен: назови оставшееся точное действие.
5. **Проверь работу.** В новой сессии Work должны быть обнаружены реальные MCP-инструменты Serena. Получи manual и подготовь проект по последовательности ниже. Затем активируй разрешённый проект, проверь эффективную конфигурацию и запроси символы настоящего исходного файла. Слушающий порт и установка коннектора эту проверку не заменяют.

## Подготовка проекта Serena1.7

Порядок проверен по установленным исходникам1.7.0. Для другой версии проверь её CLI help и шаблоны; не копируй неподдерживаемые ключи.

1. **Manual.** Вызови `initial_instructions`, если инструмент доступен. Само название контекста `agent` не доказывает, что manual предоставлен: в проверенной версии этот контекст исключает инструмент, а connection prompt содержит только просьбу вызвать его. Если полного текста нет, прочитай установленный `serena/resources/config/prompt_templates/system_prompt.yml` и доступный `get_current_config`. Назови это чтением шаблона с неразрешёнными выражениями, не вызовом инструмента или полной rendered-инструкцией. CLI `print-system-prompt` создаёт отдельный SerenaAgent, загружает все зарегистрированные проекты, может менять конфиги и запускать LS; это не безопасная замена простому чтению и не состояние действующего HTTP-сервера. Не запускай её для обхода ограничений.
2. **Новый проект до activate.** В установленном пакете найди `serena/resources/project.template.yml` и `project.local.template.yml`. Если `.serena/project.yml` отсутствует, создай его из полного shared-шаблона, задав уникальный `project_name` и известные проектные `language_servers`. Создай отсутствующий `project.local.yml` из локального шаблона; существующий сохрани. Для машинных дополнений измени local. Не создавай только local: автогенерация отсутствующего shared в1.7 копирует пустой local-шаблон поверх него. Не полагайся на определение языка по скриптам scaffold.
3. **Существующие настройки.** Прочитай оба файла. Local-список `language_servers` заменяет shared-список целиком: сохраняй все существующие явно выбранные языки/альтернативные провайдеры и их порядок, добавляя нужные. Для C#, JS/TS, Python используй соответственно `csharp`, `typescript`, `python`. Сохраняй ignore-правила, workspace folders и выбор backend; не урезай охват ради успешного запуска. Не подменяй полный шаблон двумя строками YAML.
4. **Побочные эффекты.** Альтернативный штатный `serena project create <root> --name <unique-name> --ls python` (повторяемый `--ls`) создаёт настройки и регистрирует проект глобально. `activate_project` незарегистрированного проекта также сохраняет реестр, даже при готовых YAML. Учитывай разрешения; ручная подготовка файлов не делает последующую активацию полностью свободной от внешних записей.
5. **Активация и доказательство.** Активируй абсолютный разрешённый корень, прочитай эффективные языки и выполни overview/find_symbol на настоящем исходном файле каждого используемого языка. До появления исходника отметь символическую проверку ожидающей. При ошибке проверь traceback и фактический language-server list; наличие YAML не доказательство.

## Если конфигурация уже закэширована

Повторная активация того же корня возвращает прежний объект; restart LS использует его config. Новое подключение к тому же HTTP-процессу не заменяет этот объект. Не обещай исправление этими действиями.

Условный штатный путь возможен **только** если `remove_project` уже доступен, есть другой разрешённый проект и сервер не используется другим клиентом: активировать другой свой проект → снять регистрацию целевого по проверенному уникальному имени → активировать целевой абсолютный путь → проверить эффективные языки и символы. Снятие регистрации не удаляет файлы, но меняет глобальный реестр; оно должно входить в разрешения. Не удаляй активный проект с немедленной активацией того же корня: прежний active object может сохраниться. При дубликатах имени этот путь не используй. Включение optional tool в local YAML не гарантирует его появления в уже запущенном MCP-сервере.

Если условия не выполнены, сообщи ограничение обновления кэша. Перезапуск общего сервера или изменение его контекста — отдельное вмешательство: не выполняй его в чужой активной работе и не выдавай за обычное переподключение. Продолжай только независимые разрешённые действия и явно оставь проверку Serena незавершённой.

Существующий HTTP-сервер хранит активный проект: учитывай других клиентов при его смене. Не меняй transport/порт/общую конфигурацию работающего подключения без необходимости. Не встраивай ключи или пользовательские журналы в распространяемый плагин.
