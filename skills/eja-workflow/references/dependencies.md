# Зависимости методологии в Kimi Work

Перед рабочей задачей проверь фактический каталог скиллов, подключённые MCP-инструменты и нужные CLI. Для разработки нужны Superpowers, Spec Kit, мост и Serena. Используй работающие установки; устанавливай только недостающее. Это инструкция для настройки в разрешённом пользователем объёме, не дополнительные полномочия.

Различай: **файлы есть → установлен/включён → доступен и загружен → работает**. Не вызывай сразу все фазовые скиллы: загружай их при переходе к соответствующей фазе. При продолжении используй действующую проверку, пока не изменились среда или симптомы.

## Superpowers

Источник: [obra/superpowers](https://github.com/obra/superpowers), [руководство Kimi Code](https://github.com/obra/superpowers/blob/main/docs/README.kimi.md).

Сначала проверь существующий Superpowers в **Kimi Work → Плагины** и каталог `using-superpowers`, `brainstorming`, `writing-plans`, execution/TDD/review/verification. Если отсутствует, установи из каталога Work. При отсутствии записи используй доступный Work `plugin-builder`, прочитав его актуальный SKILL.md, для преобразования официального репозитория, валидации и регистрации. Затем выполни реальную установку в Work; регистрация в «Личные» ещё не установка. Не изменяй поставляемый Superpowers ради этого плагина.

Команды `/plugins install ...` и `/new` из upstream-руководства относятся к **Kimi Code**: используй их в Work только при подтверждённой поддержке. После установки проверь каталог свежей сессии и реальный вызов `using-superpowers`.

## Spec Kit

Источник: [установка](https://github.com/github/spec-kit/blob/main/docs/installation.md), [интеграция Kimi](https://github.com/github/spec-kit/blob/main/docs/integrations/kimi.md).

Проверь `specify version`, наличие `speckit-*` и инфраструктуру целевого проекта. **`command not found` означает неудачный поиск в PATH, а не отсутствие установки. Не запускай установщик на основании одной этой ошибки.** У Work Bash и PowerShell могут быть разные PATH. Если доступен `uv`, выполни `uv tool list --show-paths` и `uv tool dir --bin`, проверь найденный исполняемый файл и вызови его по абсолютному пути. На машине Eja проверенный путь — `C:/Users/Eja/.local/bin/specify.exe`; на другой машине путь нужно обнаружить. Используй рабочий абсолютный путь в дальнейших командах либо добавь его каталог только в окружение текущего процесса; глобальное изменение PATH не требуется. Существующую неисправную установку диагностируй отдельно, не объявляй отсутствующей.

Установка разрешена только после подтверждения отсутствия CLI **и** допустимости записи в каталог установки. Если задача разрешает изменения только внутри проекта, глобальная `uv tool install` выходит за этот объём: назови ограничение и продолжай независимую работу. Не выводи право на глобальную установку из разрешения создать проектные документы или настройки. Если CLI действительно отсутствует и установка разрешена, следуй текущему официальному руководству; поддерживаемая установка — `uv tool install specify-cli`. Если нет `uv`, сначала используй [официальную инструкцию uv](https://docs.astral.sh/uv/getting-started/installation/). Не обновляй уже работающую версию автоматически и не меняй её источник на неприкреплённый Git HEAD для исправления PATH.

Перед scaffold проверь текущий каталог и возвращаемые пути. В новом разрешённом проекте актуальный маршрут — `specify init . --integration kimi --script ps --non-interactive` (на другой ОС выбери поддерживаемый тип скриптов по help). Для уже инициализированного проекта сначала `specify integration status --json`; сохраняй существующую интеграцию. `specify integration install kimi` применяй только когда это совместимо с текущей конфигурацией. Не используй слепой `--force`, удаление интеграций или перезапись пользовательских файлов.

Интеграция может создать `.kimi-code/skills/`, а обнаружение скиллов зависит от версии Work. Проверь фактический каталог и путь выигравшего скилла. Если фазовые скиллы не обнаружены, установи только недостающие в поддерживаемое этой версией хранилище либо упакуй их через Work `plugin-builder`; на машине Eja Work обнаруживал `~/.agents/skills`. Не добавляй дубликаты и не считай правила Kimi Code доказательством поведения Work. До исправления допустимое чтение установленного SKILL.md называй файловым fallback, а не вызовом Skill.

## Мост Spec Kit + Superpowers

Источник: [репозиторий и установка](https://github.com/StanislavSmetaninSSM/spec-kit-superpowers-bridge), [полный скилл](https://github.com/StanislavSmetaninSSM/spec-kit-superpowers-bridge/blob/main/spec-kit-superpowers-bridge/SKILL.md).

Проверь `spec-kit-superpowers-bridge` в реальном каталоге. Если отсутствует, установи каталог `spec-kit-superpowers-bridge/` из этого репозитория в подтверждённое хранилище Work или через его `plugin-builder`. Затем проверь обнаружение и загрузку полного SKILL.md. Мост не устанавливает Spec Kit/Superpowers сам и не требует Codex либо другого приложения агента.

## Serena

Источник: [актуальная установка Serena](https://github.com/oraios/serena#quick-start), [подключение MCP-клиента](https://github.com/oraios/serena/blob/main/docs/02-usage/030_clients.md).

Для Kimi Work используй [проверенный образец локального MCP-плагина](serena-work-plugin.md): он описывает уже работающую установку Eja, её отдельный сервер и создание такого коннектора штатным plugin-builder. Не заменяй готовый коннектор установкой другого приложения агента.

Serena — MCP-сервер, а не набор скиллов. Сначала проверь существующее подключение и его инструменты. Если сервер уже работает, сохрани его настройки и не устанавливай второй. Если отсутствует, прочитай текущий Quick Start: поддерживаемый свежий маршрут — `uv tool install -p 3.13 serena-agent`, затем `serena init` и подключение MCP через поддерживаемый интерфейс Work. Upstream рекомендует устанавливать сервер из официального источника, не по устаревшим командам сторонних маркетплейсов. Work-плагин может служить коннектором к уже установленному серверу; это не установка самого сервера.

Используй реальные команды/URL/транспорт установленной версии. Не выдумывай endpoint, не переноси чужие ключи, не меняй общий сервер или активный проект другого клиента без необходимости. На машине Eja имеется локальный HTTP-коннектор; его существование не доказывает связь. После подключения вызови доступные initial-instructions/configuration инструменты, активируй разрешённый проект и подтверди символический доступ на реальном исходном файле. Настрой языки по [адаптации Kimi](kimi-work.md#serena); до появления исходников символическую проверку отметь ожидающей, не успешной.

## Завершение настройки

После установки проверь каждый недостающий компонент по реальному каталогу/вызову/ответу инструмента, затем вернись к прерванной фазе. Не считай сообщение установщика или регистрацию достаточным доказательством. Если интерфейс требует ручного действия, назови точное действие; не обходи разрешения/аутентификацию и не заявляй, что завершил его. При ошибке назови компонент, наблюдаемую причину и зависимую фазу; продолжай только независимую разрешённую работу.
