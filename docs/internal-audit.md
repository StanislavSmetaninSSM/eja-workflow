# Internal completion audit

Local experimental candidate0.12.0 tests a native internal loop for Kimi Work on Windows. New frozen-candidate acceptance is pending; safe private main0.9.1 remains the fallback. Stop and exact-auditor Bash PreToolUse are accompanied by separate, initially disabled Agent/AgentSwarm delegation matchers. UserPromptSubmit/sessionStart/systemPrompt contributions and project AGENTS initialization are absent. It never calls `conversations.send`, types into the user input, changes permission/auto mode, starts a service or patches the application. Native Stop appends internal role:user context with system_trigger origin; the projector filters that origin from displayed user messages. Earlier0.10.3 UI observations preserved the original user bubble, with normal assistant continuation visible; each new frozen candidate needs its own observations. No native plugin preferences panel was found, so an external chat-report option is not shipped.

The native Stop hook can request **one continuation per turn**, in the exact invoking agent. Its `stop_hook` origin is filtered from displayed user messages. Normal assistant continuation and tool activity may still be visible; the first final-looking answer may already have streamed. This is not a promise of invisible processing.

1. When persisted session evidence suggests active engineering work, Stop issues a random local ticket and asks the invoking agent to run one exact auditor command. Ordinary factual conversation and questions awaiting user decisions are exempt. This eligibility signal can miss unflushed or unsupported work; no coverage is inferred from silence. A validated current native review assignment is itself eligible, including documentation-only review; other documentation-only writes and unsupported read-only work can still be missed.
2. A narrow PreToolUse hook recognizes only this plugin's fixed audit command and records the native `session_id` and `tool_call_id`. It allows other commands unchanged. Invalid/duplicate fixed invocations are refused; unsupported wrappers get no new binding and cannot establish a verified report through that wrapper. Source reads/searches/hashes remain unchanged. This is not a general shell parser or write-tool broker.
3. The actual audit tool waits up to four seconds for exactly that call id and command in the exact session's supported agent journals. It also requires this ticket's exact native `system_trigger/stop_hook` message in that caller's same open kernel task. Actor runs may end and restart inside it; kernel turn.prompt/turn.ended and canonical numeric/decimal-string ids define the boundary. Recheck must retain that boundary; a new user turn or in-turn steering invalidates it. Absent, stale, ambiguous or unsupported evidence is refused. It does not select the latest file or infer caller identity from the shared Stop session id.
4. Its redacted JSON is the ordinary tool result, routed by Kimi to the exact caller. The agent is instructed to repair applicable omissions within the original task contract and run the returned `next_action` once. The ticket permits one check and one recheck, without repeated internal prompts.

This runs **before native turn completion**. Reports say `boundary: pre_completion_tool`, `task_completion: PENDING` and `workflow_status: NOT_PROVEN`. The checker excludes only its own pending tool call; any other unmatched call or unknown record remains UNVERIFIED. A checkpoint PASS is not a completed-task or full-methodology PASS.

The checkpoint checks successful entry/order, using-superpowers and verification. Retained successful skill loads may establish availability; they do not establish current-task verification. Current-task successful implementation/execution skill evidence establishes observed implementation intent: code/test writes then require execution/TDD availability before the first such write. Code writes alone can be review probes; without that role evidence the report retains code_write_role_applicability UNVERIFIED, blocks formal recovery/PASS, and does not demand implementation phases from a reviewer. Both paths require a new successful shell check after the last observed code write. Role meaning remains manual. Main callers with current native Agent results also receive scoped child profile/entry/verification checks. Read-only child review does not require implementation/planning again. Full native Spec Kit artifacts/phases, actual RED/GREEN, approval and scope semantics, real test meaning, arbitrary shell effects and independent-review meaning still need independent review. The standalone auditor has a separate, explicit-role contract.

Original reports are created exclusively and never rewritten by recheck. `FORMAL_RECOVERED_LATE` requires relevant actual successful Skill calls and a new observed successful shell check, with no unresolved finding; suggestive arguments on another tool do not count. It does not establish that the command was a meaningful test or erase an earlier order violation. Unresolved/unknown evidence stays explicit. Do not regenerate history, fabricate RED/approval or reimplement a correct product to satisfy an ordering check.

Runtime metadata is under `KIMI_CODE_HOME/eja-workflow-audit/tickets/`, outside source and journals. It contains ticket/binding ids, paths, times and redacted reports, not user prompts, titles, reasoning, private profiles or raw tool outputs. It is not committed or uploaded. Python3.10+ with the standard library is required; the command uses `python` from Kimi's PATH. Missing runtime, hook timeout or model refusal can leave an issued ticket unused. Unused does not mean PASS.

Disabling the plugin excludes its hooks through the native engine. There is no background delivery process to keep sending. A model can still ignore the internal instruction or its tool report; the platform's one-continuation limit prevents the plugin from forcing another pass. Actual ordinary-task evidence is required before claiming any measured improvement. The original six-clean-task acceptance criterion remains unchanged.

A missing Skill may be loaded during correction without changing the original user task. Native model-tool Skill activation itself creates steering events. The guard accepts only a complete, uniquely correlated same-agent/current-prompt/current-kernel prompt.steered → skill_activation context message → turn.steer triple with matching singleton message ids, model-tool/inTurn origin and unique activation id. A matching successful Skill call/result with exact tool-call and parent UUID is required as corroboration; there is no native activation-to-tool-call foreign key. User/user-slash, combined, incomplete, duplicate, mismatched or ambiguous steering remains UNVERIFIED. Payload bodies are not retained in this correlation.

## MCP health metadata (0.10.3)

The task parser recognizes only validated native mcp.server_failed and mcp.server_failure_resolved envelopes. It checks declared fields/types, transport and resolution enums and finite nonnegative JavaScript-safe numeric time. Extra fields are deliberately rejected more strictly than native additive replay. Health metadata does not change task boundaries, caller proof, skills, completion, permissions or server readiness evidence. A resolved episode can mean recovered, needs-auth, disabled or removed; it is not proof that Serena works. Raw server/error contents are neither retained nor reported. Unknown/malformed events remain UNVERIFIED.

Frozen ordinary AJ/AK failures remain unchanged. In-memory replay of a recorded prefix tests parser compatibility; it is not a new live audit cycle or retrospective recovery of original phase order. Role inference/manual coverage and historical FAIL retention are unchanged.

## Ordering and Serena evidence (0.11.0)

For observed code access or shell work, verification_before_check requires a successful shell call submitted after a successful verification Skill result and completion of the last observed code write. Own fixed audit commands do not count as product checks or recovery verification. Meaningfulness of commands remains manual. Skill availability alone is insufficient for this temporal rule. Retained instruction availability may be reused; current checks/Serena evidence are scoped to the current kernel task.

phase_instruction_order checks known phase Skill results before the next non-Skill/non-audit operation; independent phase loads can run together if all complete before dependent work. Entry retains its stricter first-tool ordering rule. Stop eligibility now includes observed code reads and recognized symbolic queries as well as writes/shell/delegation, so code-only read review is not missed merely for having no Bash. Documentation-only or unsupported/unflushed activity can still be missed.

Observed code reads/writes require serena_symbolic_access: a successful recognized native find_symbol call with a real code-file relative_path and a nonempty matching symbol list with valid locations. Activation, empty/errors, fake similarly named tools and MCP health do not count. Only the observed plugin-serena/server and direct serena names are recognized; other providers need explicit coverage and must not be credited by substring. Source bodies are discarded. This proves bounded symbol-result evidence, not that the active project was correct, every used language covered or the symbol was understood. These remain independent checks.

Structured Agent packets are decoded before checking the canonical review text and Serena row. The row's presence does not prove its truth. Internal audit can recognize a prevented Agent only with an exact configured-home receipt, session/call/input hash/marker and native call UUID/result-parent pairing. Standalone use without those explicit trusted inputs leaves generic failed delegations unknown. Actual AgentSwarm child/lifecycle coverage remains manual; a valid pretool packet does not establish batch execution support.

## Review delivery (0.11.1)

The latest child assistant message is the native Agent return value. Stop therefore requests a self-contained original-task result, preserving substantive findings rather than replacing them with process status. Delegated review normally assigns a permitted absolute .work Markdown report and requires the parent to read it in full. An explicitly no-write review uses inline delivery and empty write roots; it grants no new permission.

Only an exact current child turn.prompt (native subagent origin, matching agentId and a single text input) projects the structural role/destination. Current successful Write/Edit with an exact absolute lexical path and call UUID/result parentUuid pairing establishes review_artifact_persisted. Existing files, other tasks/children, relative or failed/unpaired writes do not count. Inline delivery stays UNVERIFIED. File completeness, actual consent, filesystem aliases, parent full read and final delivery remain manual; scratch writes do not waive execution/TDD role uncertainty. No source bodies are retained and no global write broker or user-message transport is added.


## Assigned phases, policy and narrow invocation repair (0.12.0)

Current native implementation intent is extracted from the strict bounded versioned envelope even when readiness validation rejects omitted phases. Only exact current subagent origin/actor/kernel input establishes intent; it grants no consent, rights or readiness. Own successful UUID/actor-paired bridge/execution/TDD precedes observed implementation writes (including recognized native Serena mutations) or the first return. Verification precedes first return. Stop continuation cannot reset that first-return boundary. Unknown-role writes still stay UNVERIFIED; reviewer scratch is not assigned implementation.

Canonical policy delivery has two layers: generated full own-profile body plus exact short reference metadata, and the current child's complete successful Read before observed project work. A reference alone, old/partial/failed/unpaired/foreign/late Read is insufficient. Bootstrap own instructions and canonicalSpec reads can precede it; unknown tool/semantic effects remain manual. Legacy full packets remain admissible; current review still performs the Read. Native profile freshness and actual understanding remain independent acceptance checks.

A malformed exact own-prefix command is refused. If its phase/ticket/home identity is uniquely determined, live, same version/root/session/workspace and unconsumed, EJA_AUDIT_REPAIR returns one canonical literal command. One atomically published metadata-only receipt per ticket/phase caps the suggestion; samecall replay before consumption is idempotent. A nonblocking per-phase private lock serializes binding/repair publication, so busy phases refuse immediately; a crash-left lock makes that ticket unavailable until its unchanged TTL expires, not a general task lock. No arbitrary shell executes, TTL extends or binding/report is replaced. Foreign/ambiguous/expired/used identities and recheck without original never receive a repair. Normal literalcheck/recheck routing and originalFAIL preservation remain.

Waiting for a product decision keeps the complete actual question/context/options/spec link in the last assistant reply, without noop or new engineering just to wait. Ordinary public output delivers the task result, necessary actions or links, and material result limitations. Skill announcements, phase narration and formal audit statuses stay in internal tool results and canonical evidence. An explicit user request for process diagnostics receives that explanation. A missing material product check is disclosed briefly in plain language. Internal child handoffs and assigned review artifacts retain their complete evidence. The native live matrix remains required; unit tests of transport/receipts do not prove Kimi follows the recipe.


## Update resilience (0.12.0)

The package uses native public hooks and own files, without an application-version pin or vendor imports/patches. Known healthmetadata may gain extra fields: those are discarded and grant no caller/role/skill/readiness credit; required fields/types/values remain checked. This deliberately replaces the old exact-keyset rule for unprojected health extras only. Actor/turn/UUID, own handoff, policy content and receipt requirements are not relaxed.

Unsupported critical protocol/event/result evidence, missing/corrupt journals and unavailable caller proof are audit-availability limits, not evidence that an update happened or a methodology violation. audit_availability.status=UNAVAILABLE is terminal for automatic recovery: no next_action/recheck/engineering repair. Stop preflight returns allow/no ticket when open evidence is unsupported or unreadable; it may emit only a fixed non-sensitive reason to own-hook stderr. That diagnostic channel does not guarantee a user notification. If discovered after a ticket, the report remains UNVERIFIED/NOT_PROVEN and preserves the task result/original reports. Supported actual missing phases still FAIL with the existing bounded recheck.

The optional guard remains independent of private journals. Extra public fields do not bypass known bad packets/profile/resume/receipts. No independently trusted public toolABI version signal is present, so a future breaking rename of mandatory Agent arguments can require adaptation; guessing from malformed modelargs would weaken protection. DefaultOFF/exactscope<=1h/off CLI limit impact. No real Kimi update is forced for these tests; synthetic forward-compatibility controls do not guarantee every future app/model change. Fresh normal-task smoke after an app/model update is behavioral evidence, not implied by static schema tests.
