# Serena: проверка нового рецепта Eja Workflow 0.12.5

Дата: 2026-11-05. Проверенная версия Serena — **2.1.0**, uv **0.12.13**, CPython **3.13.15**, Windows. [Рецепт установки](../skills/eja-workflow/references/serena-work-plugin.md). Пакет устанавливался из официального PyPI, не из копии рабочей Serena.

## Что воспроизведено

У свежего сервера с context=agent initialize требовал initial_instructions, tools/list не содержал его, а реальный вызов вернул Unknown tool. Это воспроизведение ошибки прежнего рецепта. С context=ide и agent-interface=tools сервер предоставил полный rendered manual и отдельные символические инструменты. В2.1.0 activate_project требует session из manual; tools — реальное значение флага, classic не поддерживается.

Диапазоны строк здесь нулевые, как в Serena. Проверялся результат внутри ответа инструмента: имя, путь, тип, диапазон и тело, а не только HTTP/активация. Для языковых проб использовались отдельные portable Node24.22.2 и .NETSDK10.0.403/runtime10.0.14 из официальных источников с проверкой опубликованных хешей. Рабочие Node/.NET не служили неявной предпосылкой.

## Что тесты уточнили

- Python-адаптеру нужны uv/uvx в окружении сервера. Node/npm и .NET проверяются там же; .NET10+ нельзя обещать автоматически установленным адаптером.
- У builder --path задаёт родительский каталог; фактический root personal/name надо брать из stdout для validate/register.
- Активация может закончиться раньше инициализации LS. Первый config, ожидающий LS в очереди, получает бюджет старта LS. В повторном профиле холодный config занял46,54с, затем find_symbol0,69с.
- Ошибки SDK2 тестового клиента, наследуемых stdout pipes и урезанного PATHEXT были сохранены как ошибки оснастки и исправлены по конкретной причине; они не объявляются дефектами установки Serena.

## Чистота среды и границы

Использовались новые каталоги профиля, конфигурации, пакета, Python, uv/LS-кешей и отдельные loopback-порты. Это **изоляция процессов/профиля на текущей Windows**, не виртуальная машина или чистая ОС.

Первый диагностический прогон обнаружил побочный эффект uv: регистрацию тестового Python в HKCU. Он не засчитывается как полностью изолированный прогон. Тестовая ссылка впоследствии была возвращена к уже существовавшему интерпретатору рабочей Serena; исторический снимок значения реестра до теста отсутствовал, поэтому точное побайтовое восстановление прежнего реестра не заявляется.

Повторный профиль сначала выявил заимствование интерпретатора первого прогона через реестр. Этот отрицательный результат сохранён. После явной загрузки собственного Python с --no-registry, абсолютного пути и UV_PYTHON_NO_REGISTRY=1 для всего дерева процессов пакет, LS runtime и Node принадлежали повторному профилю. Настройка и символический запрос успешно повторены. Повторный профиль проверял Python; JS/TS/C# относятся к отдельным языковым пробам первого прогона. Последняя документационная правка добавляет обнаруженные условия изоляции и предпосылки, не новые серверные команды.

После независимого ревью выполнен отдельный **прогон C** с пустыми каталогами и всеми условиями изоляции до первой команды. Он не использовал пакеты, runtime или LS-кеши A/B. Первая установка и все потребительские шаги прошли без повторов: полный manual 7124 символа, session/activation, первый config 24,96с, find_symbol 0,29с и правильные имя/тип/путь/диапазон/тело. Коннектор прошёл validate0/0. Три контролируемых значения реестра совпали до установки, после неё и после завершения; собственные процессы остановлены, порт освобождён. Именно C подтверждает итоговый холодный маршрут; его языковой охват — Python.

C читал зафиксированный рецепт с SHA2566a50919d198b48ae088587abad8c70416c4faf13b47f5de2559a3d990b934be1. После запуска ревью уточнило предупреждение о записи реестра проектов Serena при activation и границы старого кэша; команды установки/сервера/MCP и условия изоляции не изменились. Исправления проверки артефактов после успешного прогона (изменившийся исходный документ, null вместо пустой переменной, порядок полей JSON) сохранены отдельно; установку или MCP ради них не повторяли.

В чистом профиле проверены создание/валидация коннектора и MCP-взаимодействие. **Установка коннектора через новый GUI Kimi Work, чистая ОС, постоянный автозапуск, восстановление после краша и все будущие версии не проверены.** Их успех не выводится из здорового TCP-порта. Рабочий сервер и коннектор Serena не обновлялись и не перезапускались. По промежуточной контрольной выборке восемь из девяти защищённых файлов совпали по хешам; хеш общего глобального конфига изменился. Источник записи не установлен, ссылок на тестовые корни в нём нет. Точное сохранение всего исходного рабочего состояния не доказано; текущий пользовательский конфиг не откатывался. Проверка личности сервера подтверждается отдельно.
